## Plain HTML

```html
<html lang="de">   <!-- data-theme="light|dark" only for an explicit switch -->
<head>
  <meta name="color-scheme" content="light dark">
  <link rel="stylesheet" href="/sebaro/fonts/fonts.css">
  <link rel="stylesheet" href="/sebaro/tokens.css">
  <link rel="stylesheet" href="/sebaro/icons/sprite.css">
  <link rel="stylesheet" href="/sebaro/css/sebaro.css">
  <!-- + the lines of brand/site-root/head.snippet.html -->
</head>
<body>
  <!-- icons/sprite.svg pasted here as it is (it hides itself); then: -->
  <svg class="sb-icon sb-icon--24" aria-hidden="true" focusable="false"><use href="#search"/></svg>
```

`/sebaro/` stands for wherever this folder is served. `sprite.css` sits in `@layer base`, so its position among the unlayered files does not matter. External `<use href="/sebaro/icons/sprite.svg#id">` works same-origin over http, not from `file://` (shared/ICONS-GUIDE.md §9.1). The quick start in the system's AGENTS.md §3 uses the system's own folder names; the map from those paths to this folder is in shared/ADOPTION.md.

## Parts of sebaro.css

The same rules as `css/sebaro.css`, cut into parts by the marks in the source (D102 (37)). Load the parts you need instead of the whole file, in the number order of their names; `01` always, and the last (forced colours and print) with every set. All of them together hold every rule of the whole file once; loaded together in this order they cascade like the whole file on the system's demo pages (checked in Chromium, systems/<slug>/CHECKS.md). ### Colour count per view (spec/03 §1.4, TEC-03)

Mark every view root with `data-sb-view="<name>"` (and `data-sb-primary-expected="0"` on a view without a primary action). `sbColourCount(view)` returns `{primary, place, status, signs, unknown, textOnColour, pass, line}`; `pass` is true with the expected number of primary-action fills, no colour without a role (`unknown` lists them) and no text on a coloured fill. Count each view in light and dark (`<html data-theme>`) and with the warm tone (`<html data-sb-tone="warm">`).

In CI (Playwright, after the page has loaded and its transitions have ended):

```js
await page.addScriptTag({ path: "<this folder>/checks/sb-colour-count.js" });
const views = await page.evaluate(() => [...document.querySelectorAll("[data-sb-view]")]
  .map((v) => ({ view: v.dataset.sbView, ...window.sbColourCount(v) })));
const failed = views.filter((v) => !v.pass);   // fail the run with failed.map((v) => v.line)
```

On a development page: `<script src="<this folder>/checks/sb-colour-count.js"></script>` at the end of the body writes each view's line („Farbprüfung: Hauptaktion 1 · … · bestanden“) into `[data-sb-colour-count="<name>"]` and counts again after `sb-theme-change`. The line is German only (a check, not UI text). Not read: pseudo-element paints (checkbox marks, chip frames, slider handles) and focus outlines.

## Share images

One share image per page with a title of its own, 1200 × 630, light ground, rendered **in the site's own build** from the one template of sebaroDesign (D96, spec/09 §18.1). The site writes a page list from its own pages; `brand/og/render.mjs` fills `brand/og/template.html` once per page and renders it in Chromium. Needs Node 20+ and Playwright with Chromium (Chromium only, like the CI under D96 (b)): `npm install --save-dev playwright`, then `npx playwright install --only-shell chromium`. Offline: every request that is not local (`file:`, `data:`) is blocked.

```sh
node <this folder>/brand/og/render.mjs --pages og-pages.json --out public/og --head build/og-head
```

`og-pages.json` follows `brand/og/pages.schema.json` (the script checks it against that file):

```json
{
  "$schema": "./sebaro/brand/og/pages.schema.json",
  "site": {
    "product": "retrobeam",
    "name": "<site name>",
    "origin": "https://<host>"
  },
  "pages": [
    {
      "id": "start",
      "url": "/",
      "type": "website",
      "title": "<the start page's title>"
    },
    {
      "id": "<page id>",
      "url": "/<section>/<page>/",
      "title": "<the page's own title>",
      "path": [
        "<site name>",
        "<section>",
        "<page>"
      ],
      "readingMinutes": 12,
      "date": "2026-04-26",
      "description": "<the page's meta description>"
    }
  ]
}
```

Per page it writes `<out>/<output>.png` (24-bit RGB, no alpha) and `<head>/<output>.head.html` with the head tags of spec/09 §18.1 (canonical, description and og:description when the page has one, og:type, og:site_name, og:locale, og:url, og:title, og:image absolute, its width, height and alt, twitter:card), plus `<head>/head.json` with the same tags as data for a framework. Include the snippet in the page's `<head>`; the site still writes `<title>`, the language alternates (spec/09 §18.2) and serves the PNGs under `site.origin` + `site.imageBase` (default `/og/`). Keep `--head` out of the published folder.

It fails loud (exit 1, the page id named, no image and no head snippet written for that page): a title that needs more than three lines or a word wider than its line (never cut, never set smaller; mark break points in long compounds with U+00AD), a path, name or foot wider than its line, a character sebaro Sans does not cover, a font that did not load, a blocked request, and in the written PNG a size other than 1200 × 630, an alpha channel or a ground other than `color.bg` light. Exit 2: the page list does not match the schema, or a file of this export is missing (a product's tile needs `--product <id>` on the export; `--product studio` exports every tile). The same input gives the same bytes with the same Chromium. German and English words (`site.lang`); right to left is not supported.

Rules, components and recipes: `systems/sebaro/AGENTS.md` and `spec/09-platform-web.md` in sebaroDesign.

D40: screens keep the core cobalt/lime palette. Apply `data-product` only on an inline sign tile, never on the HTML root or a screen. Web and Tauri exports use the same variable WOFF2 (D66, D77).

## Keep in sync

```sh
python3 <sebaroDesign>/tools/export_system.py sebaro --target web --out <this directory> --product retrobeam --no-editor
python3 <sebaroDesign>/tools/export_system.py --verify <this directory>
python3 export_system.py --verify <this directory> --files-only    # CI without a sebaroDesign checkout
```

`--verify` exits 1 when a file here was edited or deleted, when its source in sebaroDesign changed, when a fresh export would add or drop files, or when a gate of the system fails; it needs a sebaroDesign checkout. `--files-only` needs only `export_system.py` and this folder: it catches edits and deletions here, **not** source drift. Re-export to update.

Add `--from-commit <rev>` to both commands for a clean export from a commit rather than from sebaroDesign's working tree, which often holds an unfinished round; the record names the commit and `--verify --from-commit <rev>` compares with it.

### In the product's CI, with Node alone

`checks/verify-export.mjs` checks this folder against `sebaro-export.json` like `--files-only` does, with Node 20+ and nothing else (no Python, no copy of `export_system.py`, no sebaroDesign checkout):

```sh
node <this folder>/checks/verify-export.mjs             # this folder: the one above the script
node <this folder>/checks/verify-export.mjs --strict    # also fail on a file the record does not name
node <this folder>/checks/verify-export.mjs <another export folder> [--strict]
```

One line per finding (`FAIL  missing in target: …`, `FAIL  edited in target: …`, `WARN  not part of the export: …`) and a summary line. Exit 0 no errors, 1 a missing or edited file (with `--strict` also a file the record does not name), 2 usage error or a missing or unreadable `sebaro-export.json`. `--strict` never counts `sebaro-export.json` itself, dotfiles or anything in a dot folder; anything else the product puts into this folder fails it, so keep the product's own files outside (an installed package's `package.json` fails it too: run it there without `--strict`). Like `--files-only` it does **not** see source drift or the system's gates.
